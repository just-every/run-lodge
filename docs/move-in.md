# Move in from Workable

Bring your Workable history. Preview the full export first; nothing is written
until you commit that exact preview.

## Get the export

Ask Workable support for the **full data export** ZIP. The candidate CSV report
is not enough: it leaves out resumes and files.

## Preview, then commit

Open **Move in**, choose the **Workable export ZIP** and press **Preview
package**. The preview writes nothing. It shows how many records it read, how
many it will import and how many it set aside, with the reason for each row set
aside, resumes named but missing, files that match no candidate and what is not
carried over.

Press **Commit this exact preview** to import exactly what you saw. Committing
the same package again creates nothing new. A batch that stops part way can be
resumed from **Import batches**.

## What comes across

| Workable | Lodge |
|---|---|
| Jobs | Vacancies marked imported, kept as history |
| Candidates | Candidates, one application per job, with the source stage |
| Files | Documents with their original bytes |
| Comments, ratings, events, messages | Imported history on the application |
| Members | Names and roles only, with no access to Lodge |

Imported records never grant access, send anything or reopen a job.

## Undo

**Undo unchanged records** removes what the batch imported, except records a
person has since changed or that another record relies on. The batch details
say which were kept and why.

Packages up to 20 MB are accepted, with files up to 1 MB each.
